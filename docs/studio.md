# IntentLang Studio feature guide

IntentLang Studio is the local authoring workbench for business applications
and visual pages. It runs on localhost, works without an AI provider, and keeps
checking, saving, and generation as separate explicit actions.

## Choose an authoring path

### Code

Use **Code** when you want to write or edit the formal IntentLang business
language directly. Existing non-empty `.intent` files open here by default.

The workspace is split into:

- A source editor on the left.
- A compiler inspector on the right.
- A status bar showing validation and unsaved state.

### App Builder

Use **App Builder** to create a supported CRUD-style application through a
guided four-step flow:

1. **Describe** the app using the finite patterns supported by the offline
   interpreter.
2. **Review** the exact proposed IntentLang source, assumptions, type warnings,
   and unsupported requests.
3. **Build** only after acknowledging any omitted capabilities.
4. **Open app** in a local preview when the generated app does not require
   authentication setup.

App Builder is not unrestricted prompt-to-code. Unsupported meaning is listed
instead of guessed or silently removed. The full accepted description
vocabulary is in [Describe App mode](description-mode.md).

### Visual Language

Use **Visual Language** for a separate controlled-English grammar that builds
browser pages and interfaces. It covers elements, text, layout, CSS properties,
forms, animation, and safe interactions, and compiles to standalone HTML.

Visual Language does not define the entities, API, database, roles, or
workflows generated by the business language. See the
[visual language guide](visual-language.md).

## Code workspace

### Write IntentLang

**Write IntentLang** is the direct source editor.

- Autocomplete offers valid statement snippets and names already declared in
  the source.
- `Tab` or `Enter` accepts the selected completion.
- Arrow keys move through completion choices.
- `Escape` closes the completion list.
- Line numbers follow the current source.
- A prose warning appears when text looks like an app description rather than
  controlled grammar.

The prose warning can move the text to **Describe App** or open valid templates.

### Describe App

**Describe App** inside the Code workspace uses the same deterministic offline
interpreter as App Builder. It is useful when you want a proposal but also want
the editor and compiler inspector nearby.

It provides two paths:

- **Use offline guided interpretation** is always available and uses finite,
  versioned rules.
- **Ask configured AI** is enabled only when Studio was started with an AI
  provider. AI output remains an untrusted proposal and must pass the compiler.

Applying a proposal updates the editor only. It does not save the source or
generate artifacts.

## Editor actions

### Check

**Check** parses and validates the current editor contents without writing to
disk. The shortcut is `Ctrl+Enter`.

The first diagnostic appears above the editor. **Show all problems** opens the
complete Problems inspector.

### Format

**Format** computes canonical controlled-English formatting and shows a diff
before changing the editor. The shortcut is `Ctrl+Shift+F`.

Applying formatting changes the editor only. Save remains separate.

### Save

**Save** asks for confirmation before overwriting the source file. The shortcut
is `Ctrl+S`.

The status bar and unsaved marker distinguish the editor buffer from the last
saved file.

### Generate App

**Generate App** validates the source and presents a generation plan before
writing artifacts. The plan identifies output files and operations requiring
review.

Generation is separate from saving: you can inspect or save source without
generating, and a proposal never triggers generation automatically.

### Templates

**Templates** loads a known valid starter into the editor. If the editor has
unsaved changes, Studio asks before replacing them.

### AI Assist

**AI Assist** is optional and disabled by default. When configured, it can
propose source changes from a description. It cannot write files, execute
commands, bypass diagnostics, or change compiler semantics.

Provider setup and trust boundaries are documented in
[Optional AI assistance](ai-assistance.md).

## Compiler inspector

### Problems

Lists parser and semantic diagnostics. Selecting a diagnostic moves the editor
to its source location. A valid program reports **No problems detected**.

### Application Model

Shows the compiled business model, including:

- Entities and fields
- Relationships
- Actions and workflows
- Roles and permissions
- Expanded policies and declarations
- Project modules
- Security and safety information

This view explains what the compiler understood; it is not a second source of
truth.

### Canonical Source

Shows normalized IntentLang emitted from the compiler model. Canonical source
is useful for reviewing formatting and stable language meaning.

### Raw IR

Shows the typed intermediate representation as JSON. This is primarily for
compiler debugging, tooling integration, traceability, and advanced review.

## App Builder details

### Existing source

When Studio opens a non-empty file, Code is the primary workspace. App Builder
remains available from the top navigation and warns that building a new
proposal can replace the source only through an explicit confirmed action.

### Unsupported requests

App Builder displays unsupported capabilities and unrecognized fields in the
review step. You must acknowledge them before a partial proposal can be built.
Acknowledgement does not implement those capabilities.

### Preview

Unauthenticated generated apps can be started and stopped from Studio.
Authenticated apps instead show the required bootstrap environment variables
and run command. Studio does not place passwords in source.

## Persistence and safety

- Studio listens on localhost.
- Checking never writes files.
- Formatting requires applying a preview and still does not save.
- Proposals update the editor only.
- Saving requires confirmation.
- Generation shows a plan before writing.
- Unsupported description content is visible and requires acknowledgement.
- AI is optional and is never the compiler authority.

## Theme and responsive layout

**Dark mode** and **Light mode** change the Studio palette without changing
source or generated output. The workspace adapts to desktop, tablet, and mobile
widths. On smaller screens, the editor and inspector stack vertically and the
authoring navigation remains horizontally accessible.
