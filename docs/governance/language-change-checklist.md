# Language Change Checklist

- [ ] Problem and user scenario are documented.
- [ ] Permanent normative rule IDs are assigned.
- [ ] Grammar and canonical form are explicit.
- [ ] Types, resolution, evaluation order, effects, and IR are specified.
- [ ] Ambiguity and context-closure cases are listed.
- [ ] Security, privacy, authorization, ownership, and secret effects are reviewed.
- [ ] Compatibility class and migration behavior are documented.
- [ ] Every diagnostic is inventoried and actionable.
- [ ] Database, runtime, UI, manifest, trace, Studio, and tooling obligations are covered.
- [ ] Positive, negative, ambiguity, canonical, property, runtime, compatibility,
      traceability, and backend-parity evidence is added where applicable.
- [ ] Documentation and runnable examples are updated.
- [ ] Semantic fingerprints and historical fixtures are reviewed.
- [ ] The feature remains experimental until every graduation criterion passes.
